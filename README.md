# Лабораторная работа 5 — вариант 2

Бинарное дерево поиска сотрудников. Поля: имя, отдел, зарплата.
Ключ — зарплата; две записи с одинаковой зарплатой считаются дубликатами,
даже если имя и отдел различаются. Критерий варианта — точное совпадение отдела.
Демонстрация использует отдел «ИТ» и шесть сотрудников.

## Контракт

| Класс | Данные и операции | Владение и специальные члены |
| --- | --- | --- |
| `Employee` | Имя и отдел — строки, зарплата — конечный неотрицательный `double`. Пустые строки допустимы для эталона. `<` и `==` сравнивают только зарплату без eps. Геттеры const. | Копирование и перемещение разрешены. Каждый конструктор увеличивает статический счётчик; деструктор уменьшает. Присваивание число объектов не меняет. |
| `EmployeeTree::Node` | Запись, левый и правый потомки. Определён только в employee_tree.cpp. | Дети в unique_ptr, запись в shared_ptr. Обратных владеющих связей нет. |
| `EmployeeTree` | Insert, Find, Remove, size, height, Select, InOrder, ReverseOrder. Вставка дубликата и удаление отсутствующего ключа возвращают false. | Копирование запрещено, перемещение забирает корень и обнуляет размер источника. Все специальные члены определены в cpp, где Node полный. |
| `Selector` | Абстрактный const-метод Matches и виртуальный деструктор. | Не хранит дерево и не владеет записями. Конкретные критерии копируются и перемещаются автоматически: у них только значения. |
| `DepartmentSelector` / `AllSelector` | Сравнение отдела с полем критерия / принятие всех записей. | Дерево получает базовый интерфейс по const-ссылке, не сохраняет его. |
| `Selection` | size, capacity, empty, At, Add. At бросает out_of_range при неверном индексе. | Собственный массив unique_ptr<weak_ptr<const Employee>[]>. Правило пяти; копия создаёт отдельный массив, перемещение оставляет источник с размером и вместимостью 0. |

Поиск возвращает `weak_ptr<const Employee>`, чтобы внешний код не мог изменить ключ
и нарушить BST. Эталон создаётся как `Employee(зарплата)` — остальные поля пустые.
shared_ptr нужен для возможности создать weak_ptr; unique_ptr записи такого наблюдения
не поддерживает. Дерево хранит единственную постоянную сильную ссылку на запись.
Временный результат lock() продлевает жизнь записи до своего уничтожения.
Поэтому перед проверкой истечения ссылки такой временный владелец должен выйти из области видимости.

Удаление листа уничтожает узел. При одном ребёнке его unique_ptr переносится на место
узла. При двух детях переносится shared_ptr преемника (минимума правого поддерева),
а сам преемник заменяется своим правым ребёнком. Объект удалённой записи уничтожается,
а идентичность объекта преемника сохраняется. Старые weak_ptr безопасно истекают,
когда исчезает последний сильный владелец; размер старой выборки при этом прежний.

Select выполняет один симметричный обход, проверяет критерий и сразу добавляет ссылку.
Время O(n), стек O(h), массив O(k). При заполнении вместимость удваивается,
поэтому Add амортизированно O(1). Порядок результата — по возрастанию зарплаты;
ReverseOrder использует тот же вспомогательный обход с обратным направлением.
Пустое дерево даёт пустую выборку и высоту 0; лист имеет высоту 1.
Insert, Find, Remove работают за O(h). Дерево не балансируется, в худшем случае h = n;
рекурсивный обход и освобождение ограничены доступным стеком.

## Сборка и запуск

Нужны CMake 3.20+, GNU GCC с C++20 и Google Test (если не установлен, CMake скачает v1.15.2).
На этом Mac установлен g++-16; на Linux можно указать g++.

```sh
cmake -S . -B build -DCMAKE_CXX_COMPILER=g++-16 -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j4
./build/lab05_main
ctest --test-dir build --output-on-failure
./build/tests
```

ASan и предупреждения `-Wall -Wextra -Wpedantic` включены всегда для всех целей.
На Linux с поддержкой LSan можно дополнительно запустить
`ASAN_OPTIONS=detect_leaks=1 ./build/tests`.
На macOS проверка LSan не гарантирована; отдельно тестируется возврат счётчика
живых Employee к нулю. Счётчик не предназначен для многопоточного использования.

Проверено: GNU GCC 16.2.0, macOS, Debug с ASan. Все 19 тестов проходят;
демонстрация после удаления зарплаты 90000 выводит [expired] в прежней выборке.
Тесты проверяют три случая удаления, сохранение объекта преемника, порядок обходов,
отбор по отделу, независимость критериев, правило пяти выборки, перемещение дерева,
границы массива, дубликаты, невалидные зарплаты и освобождение записей.
